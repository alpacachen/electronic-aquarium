# 交互测试耗时记录

最后更新：2026-08-11

## 结果

交互测试跑在 Chromium 的 SwiftShader 软件 WebGL 上，耗时会随机器和 GitHub runner
略有变化。PR #42 的本地基准如下：

| 阶段 | 测试条数 | `pnpm test` |
| --- | ---: | ---: |
| 合并场景前 | 60 | 约 227 秒 |
| [PR #42](https://github.com/alpacachen/electronic-aquarium/pull/42) 合并后 | 30 | 约 119 秒 |

测试数量和耗时都约减半。更早的 [PR #41](https://github.com/alpacachen/electronic-aquarium/pull/41)
还减少了长时间采样循环里无用的最终 WebGL 绘制，并合并了一批对称的重复用例。

## 为什么有效

- 每条用例都会从 `openAquarium()` 打开一次完整鱼缸。若多个断言共享同一个初始场景，把
  它们放进同一个 `it()`，只需付一次浏览器、Canvas、模型和加载幕布的启动成本。
- 场景内长时间采样仍用 `letTimePass()` 推进固定步长；只读取模拟状态时可以传
  `letTimePass(seconds, false)`，跳过最后一次无用绘制。需要检查鱼身几何、包围盒或实际
  渲染结果时，保留默认绘制。
- `fileParallelism` 必须保持 `false`。多个文件同时抢同一个软件光栅化器时，单独能过的
  测试会一起变慢甚至超时。

## 后续写测试的边界

合并测试前先确认 Given 完全相同，而且第二段不会依赖第一段改变后的状态。下面两种情况
应保持独立用例：

- 前置场景不同，例如一个从标准缸开始、另一个从迷你缸开始。
- 断言依赖渲染后的几何状态，例如模型 `Box3`、骨骼或材质更新；不能为了省一次绘制而关闭
  最后一帧。

提交前运行：

```bash
pnpm check
```

PR 描述中写明测试条数和耗时对比，后续优化才有可核对的基线。
